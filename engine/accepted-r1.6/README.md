# EveJS Private Identity Transfer — r1.6

Selective cross-version migration helper for a local EveJS world.

The **classic pass** transfers private player/corporation identity and ordinary assets into a freshly initialized target release while leaving universe/world runtime and player structures behind. Player structures and everything rooted inside them remain deferred for a later optional structure pass.

## Why r1.6 exists

Real 0.12.7 -> 0.12.7.1 field testing proved most of r1.2 worked: accounts/characters, ships, fittings, inventory, corporation hangars, skills/queues and bookmarks survived a fresh-target migration. The test also exposed two omissions outside that core DB graph:

1. the authoritative personal wallet is **not** `characters.balance`; current ISK/AUR/PLEX and wallet journal live in `walletAuthorityState` under `character:<characterID>`;
2. portrait JPEGs live separately in `_local\gameStore\images\Character` and must be copied by preserved characterID.

r1.5 added both surfaces deliberately. Field investigation after v0.1.2 then proved that blueprint inventory rows were transferred without their `industryBlueprintState` companions. r1.6 adds a narrowly scoped inactive-blueprint companion pass while retaining the r1.5 structure and world-state policy.

For transferred blueprint instances, r1.6 preserves `itemID`, `typeID`, material efficiency, time efficiency, original/copy state, and remaining copy runs. Active `jobID`, installed location `2003`, malformed identity/state, and missing copy state are blockers. `industryJobs` are not transferred. `jobID` is normalized to `null`; `lastCompletedJobID` and `lastCancelledJobID` are cleared to prevent target job-history collisions. A missing singleton-1 original state is safely synthesized as EveJS's canonical ME 0 / TE 0 / unlimited-run default. A missing copy state is never invented.

## Classic transfer — included

- accounts and account settings;
- characters with original IDs preserved;
- referenced player corporations and alliances;
- selected corporation/alliance runtime identity/settings;
- ordinary personal/corporation inventory and nested item graph;
- inactive companion state for transferred blueprint instances only;
- skills, skill plans, queues, skill-trading state, expert systems;
- **walletAuthorityState per selected character**:
  - current ISK balance;
  - AUR balance;
  - PLEX balance;
  - balanceChange state;
  - wallet journal/history;
- LP wallets;
- saved fittings;
- mailboxes/messages;
- notifications;
- bookmarks/folders/groups;
- map telemetry;
- EverMark entitlement state;
- selected ship module grouping / dirt / kill-counter / logo-fitting state;
- NPC-station corporation offices and ordinary corporation hangars.

## Player structures — deferred

The classic pass does not import a player structure or any inventory rooted inside it. This includes ships, cargo, corporation-office contents, fitted structure services/core, and nested descendants. Nothing is automatically dumped onto an NPC station.

Unknown dynamic locations still fail closed.

## Portrait media

Portraits are a separate media stage. r1.6 provides a `portraits` command that only copies files whose filename starts with a selected preserved `characterID` from:

```text
<source>\_local\gameStore\images\Character
```

to:

```text
<target>\_local\gameStore\images\Character
```

It is dry-run by default. `--apply` backs up every overwritten target portrait and hash-verifies each copied file.

Characters without portrait files are reported but are not a blocking error; canonical hidden/test fixtures may legitimately have no portrait set.


### 3. Import dry-run on fresh 0.12.7.1 target

```powershell
$Root = "G:\EVESP\EveJS-CodexLab\EveJS-0.12.7.1-test"
$Bundle = "$RunDir\private-state-0.12.7-r1.6.json"

node .\private-identity-transfer.js import `
  --target-root $Root `
  --in $Bundle `
  --replace-existing
```

No writes occur without `--apply`.

### 4. Apply only after dry-run review

```powershell
node .\private-identity-transfer.js import `
  --target-root $Root `
  --in $Bundle `
  --replace-existing `
  --apply
```

Apply creates a coherent SQLite backup, imports item and blueprint companion rows inside one transaction, verifies wallet rows and blueprint semantics, checks SQLite integrity, confirms forbidden world-state fingerprints are unchanged, and checkpoints the WAL.

## Safety

- target server must be stopped for DB import;
- source server should be stopped for the cleanest export snapshot;
- static authority comes from the target/source release JSON, not old SQLite static rows;
- old player-structure/world runtime is never imported by the classic pass;
- username/account-ID mismatches fail closed;
- unresolved dynamic locations fail closed;
- fixture replacement requires explicit `--replace-existing`;
- no DB write occurs without `--apply`;
- portrait copy also requires explicit `--apply`.

r1.6 is a **local release candidate**, not Accepted until the corrected blueprint path is gameplay-confirmed.
